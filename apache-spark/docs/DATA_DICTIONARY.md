# Data Dictionary

Generated by `python -m scripts.generate_data_dictionary` from the schemas actually written to the lake.

Conventions: Silver/Gold column names are the Kaggle names in lower_snake_case. Amounts are in the (unspecified) currency of the Kaggle data. `DAYS_*` / `MONTHS_*` are relative to the CURRENT application date (negative = before).

## 1. Silver tables (cleaned, typed, one per source table)

| Table | Logical source | Origin | Grain | Primary key | Foreign keys |
|---|---|---|---|---|---|
| silver/application_train | loan_application_system | ORIGINAL | 1 row = 1 current loan application (SK_ID_CURR) | sk_id_curr | — |
| silver/application_test | loan_application_system | ORIGINAL | 1 row = 1 current loan application (SK_ID_CURR), no TARGET | sk_id_curr | — |
| silver/bureau | external_credit_bureau | ORIGINAL | 1 row = 1 credit reported by another institution (SK_ID_BUREAU) | sk_id_bureau | sk_id_curr → application |
| silver/bureau_balance | external_credit_bureau | ORIGINAL | 1 row = 1 bureau credit x 1 month (SK_ID_BUREAU, MONTHS_BALANCE) | sk_id_bureau, months_balance | sk_id_bureau → bureau |
| silver/previous_application | previous_loan_system | ORIGINAL | 1 row = 1 previous Home Credit application (SK_ID_PREV) | sk_id_prev | sk_id_curr → application |
| silver/installments_payments | installment_payment_system | ORIGINAL | 1 row = 1 payment record of 1 installment of a previous loan (an installment can have several partial-payment rows) | — (event table) | sk_id_prev → previous_application; sk_id_curr → application |
| silver/POS_CASH_balance | pos_cash_system | ORIGINAL | 1 row = 1 previous POS/cash loan x 1 month (SK_ID_PREV, MONTHS_BALANCE) | — (event table) | sk_id_prev → previous_application; sk_id_curr → application |
| silver/credit_card_balance | credit_card_system | ORIGINAL | 1 row = 1 previous credit card x 1 month (SK_ID_PREV, MONTHS_BALANCE) | — (event table) | sk_id_prev → previous_application; sk_id_curr → application |
| silver/synthetic_traffic_profile | synthetic_customer_behavior | SYNTHETIC | 1 row = 1 SK_ID_CURR (SYNTHETIC traffic profile, not real data) | sk_id_curr | sk_id_curr → application |

Every Silver table also carries the lineage columns `_source_id, _origin, _ingest_id, _ingested_at, _silver_processed_at` and the quality flags described in `reports/data_quality/CLEANING_RULES.md`.
